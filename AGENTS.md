# Інструкції для агентів цього репозиторію

## Прочитати перед роботою

1. [Оригінальну умову та застереження щодо її актуальності](docs/assignment/README.md)
   і, для точних формулювань, [повний текст](docs/assignment/kaggle-original.txt).
2. [Поточні завдання та відповіді агентів](docs/AGENT_COORDINATION.md).
3. [Коли CSV готовий до подання](docs/submission_protocol.md).
4. [Оновлений протокол повних даних і ціль 0.28+](docs/full_data_protocol.md).
5. Для локального виконання — [watchdog](docs/local_watchdog.md) та
   [протокол ефективного пошуку](experiments/efficient_search.md).
6. [Посилений відбір та кеш оцінок](docs/selection_policy.md) і
   [аудит вимог лабораторної](docs/LAB_PROGRESS.md). Нові запуски не можуть
   використовувати застарілий AP-only gate як дозвіл на promotion/export.
7. Для оптимізації самого циклу — [вимірювання training throughput](docs/training_performance.md).
   Не називати зменшення loss-readback або CPU-тест виміряним GPU speedup/AP gain.

## Режим спільної роботи

Користувач доручив передавати умову й робочі інструкції між вебсеансом і
локальним Codex через цей GitHub-репозиторій. Це асинхронний обмін файлами:
push/pull не створюють спільної пам'яті моделей або безперервного live-з'єднання.

Перед новим рішенням перевіряти останні coordination notes і фактичний стан
локальної машини. Після суттєвого етапу додавати коротку датовану відповідь у
`docs/AGENT_COORDINATION.md`: що перевірено, які вимірювання отримано, що готове
до Kaggle, що блокує роботу, який наступний крок. Посилатися на relative paths,
SHA та метрики; не вивантажувати нерозібрані логи. Записи не вигадувати й не
переписувати давні невдалі результати як успіхи.

Оновлення coordination notes і перевірених результатів належать до дорученого
обміну через Git. Stage лише потрібні файли; не робити `git add .` для великих
runtime-каталогів. Узгоджувати нову remote head без force push. Автоматичного
Git-push за розкладом тут немає; не додавати його без урахування реального
дедлайну. Для поточного доручення користувач прямо попросив опублікувати умову
та правила подання.

## Експерименти й артефакти

- Локальний агент має перевіряти процеси/стан безпосередньо. Вебагент не має
  автоматичного доступу до локального термінала; надісланий раніше лог не є
  поточним вимірюванням.
- Використовувати готові навчені ваги та сумісний стан оптимізатора. Зберігати
  перевірений public-best source; не починати модель заново через звичайний
  restart наглядача. Не переривати здорове навчання заради зміни документації.
  Для CV не переносити fine-tuned ваги у fold, validation якого вже брала участь
  у їхньому навчанні; джерело pretrained initialization має зберігати незалежність
  кожного оцінюваного fold.
- Дотримуватися shared GPU lease; DataLoader workers не є незалежними training
  jobs. Тиха GPU під час CPU COCO metrics не доводить зависання.
- Великі datasets, checkpoints, predictions, особисті шляхи, телеметрія машини
  та credentials лишаються локально. Runtime root брати з конфігурації
  watchdog/експерименту або `CVLAB_LOCAL_WORK`, не вшивати особисті mount paths
  у публічні документи. Не друкувати й не комітити токени.
- Не підмінювати full validation оцінкою на 512 кадрах, OOF — одним fold,
  завершене навчання — smoke-run, public score — локальним AP.
- Умови дозволяють AI-код, але забороняють AI-written reports. Не писати
  фінальний академічний звіт або студентські висновки. Технічна документація
  коду, відтворюваності та операційні нотатки мають лишатися окремими.

## Подання

Дотримуватися `docs/submission_protocol.md`. Поточний watchdog готує файли та
повідомлення; він не відправляє CSV на Kaggle. Доручення описати готовність не
означає, що CSV уже подано. Позначати SUBMITTED/SCORED лише за фактичною
відповіддю Kaggle. Ціль public baseline — `0.2216324580`; досягнення підтверджує
оцінка самого змагання. Нова робоча ціль користувача — `0.28+`; її не підміняти
формальним baseline або вже отриманим score. Для фінального навчання повних
train+val застосовувати окремий протокол, а не contaminated fold-validation.
Актуальні спостереження — в
`experiments/leaderboard_results.json`.
