# Оригінальна умова лабораторної

Змагання: [Multiple Object Video Detection — HW 2, UCU AI 2026](https://www.kaggle.com/competitions/multiple-object-video-detection-hw-2-ucu-ai-2026).

[kaggle-original.txt](kaggle-original.txt) — повний текст, який користувач вставив
із Kaggle у розмову. Файл скопійовано дослівно, включно з початковими перенесеннями
рядків; контрольна сума та походження — у [source.json](source.json).
Це збережений знімок, а не підтвердження поточного змісту сторінки Kaggle.

Ця сторінка — навігація вимогами. Вона не є студентським звітом або заміною умови.

## Обов'язкові складові

| Частина | Що вимагає надана умова |
| --- | --- |
| Дані та preprocessing, 1 бал | Розподіл класів, розміри об'єктів, щільність сцен за відео; перевірка GT на зображеннях; ignored regions і non-target classes; відтворювані transforms; поділ за відеопослідовностями. |
| Two-stage anchor-based, 1 бал | Pretrained Faster R-CNN/Cascade R-CNN; дослідити щонайменше два релевантні параметри; mAP, AP50, AP_small і швидкість; щонайменше три failure cases із поясненнями. |
| One-stage anchor-based, 1 бал | RetinaNet/SSD за порівнюваного протоколу; tuning anchors, focal loss або assignment; мотивація за статистикою даних; порівняння з tuned two-stage. |
| One-stage anchor-free, 1 бал | FCOS/CenterNet/відповідний YOLO; щонайменше два релевантні параметри; діапазон пошуку, обрані налаштування; результати за розмірами об'єктів і порівняння сімей. |
| Query-based, 0.75 бала | RT-DETR/Deformable DETR за порівнюваного compute budget; tuning queries/matching/losses/LR; пояснення bipartite matching; графік validation mAP за часом проти CNN; аналіз малих/щільних об'єктів та збіжності. |
| Власний pipeline, 1.25 бала | Обґрунтоване продовження порівнянь; проміжні експерименти, які розрізняють вплив даних/inference і вплив моделі; відтворюваний фінальний pipeline. |
| Звіт, 2 бали | Власноруч написаний студентами компактний звіт: методологія, мотивація, успішні й невдалі експерименти з вимірюваннями, фінальна модель та інструкція запуску. Рекомендовано близько 1500 слів. |
| Private leaderboard, 2 бали | Фінальний рейтинг; вибір двох найкращих рішень за внутрішньою оцінкою, а не лише public score. Умова прямо вимагає перевищити baseline. |

У загальному вступі до чотирьох модельних рубрик окремо зазначено щонайменше два
експерименти понад baseline із hyperparameter tuning і loss modification.
Дотримуватися конкретних вимог кожної рубрики; не вважати одну наявну конфігурацію
доказом виконаного tuning або зміненого loss.

Потрібні sequence-level cross-validation та out-of-fold evaluation, однакові
дані/метрики для коректних порівнянь і навчання learned preprocessing тільки на
training частині fold. Підготовлені folds, fold0 або smoke-run самі по собі не
доводять виконання повного CV/OOF.

## Формат здачі та авторство

- Код і звіт — окремі deliverables за викладацьким GitHub template; notebook із
  виводами не замінює звіт. Саме посилання на офіційний template у вставленому
  тексті відсутнє: перевірити його в курсі, не вигадувати адресу.
- Звіт публікується через GitHub Pages; repository link подається в LMS. Якщо
  працюють удвох, обидва учасники мають бути collaborators із реальними meaningful
  commits, обидва подають посилання й проходять індивідуальний захист.
- Репозиторій повинен бути public і доступним для перевірки відповідно до умови.
- У розділі **AI usage** дозволено AI для коду та прямо заборонено AI-written
  reports. Агент може допомагати з кодом і технічними інструкціями, але не писати
  фінальний студентський звіт або висновки від імені студента.
- Зовнішні джерела коду/ідей треба цитувати; обмін кодом з іншими учасниками
  заборонений. Не імітувати авторство або коміти іншого учасника.

## Бонуси та неповні місця знімка

Умова описує temporality (+1), visualization (+1), architectural decisions
(до +3). У пункті Visualization міститься вимога W&B logging: curves,
configurations і validation predictions із bounding boxes для required models,
доступні оцінювачам. Не стверджувати наявність цих матеріалів без перевірки.

Розділ Your Pipeline згадує «Both parts below», але окремі два підпункти у
наданому знімку не наведені. Не домислювати їхній зміст: за потреби звірити
поточну сторінку курсу/Kaggle.
